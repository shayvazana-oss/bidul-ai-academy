# חיבור ביקורת התוכן במעבדת הלינקדאין

בודק הפוסט במעבדה עובד בשתי קומות:

| | מה נבדק | איפה רץ | עלות |
|---|---|---|---|
| **קומה 1 — בדיקת צורה** | שורת פתיחה, קלישאות, מבנה, אורך, סיום, האשטגים | בדפדפן של המשתמש | 0 |
| **קומה 2 — ביקורת תוכן** | האם יש אמירה אמיתית, שורות גנריות, ו**הבטחות שאי אפשר להגן עליהן** | פונקציה בשרת שקוראת ל-Claude | לפי שימוש |

קומה 1 עובדת תמיד, גם בלי שרת. המסמך הזה מסביר איך להפעיל את קומה 2.

---

## למה נדרש שרת בכלל

מפתח API של Anthropic הוא סוד. אם הוא יושב בעמוד HTML סטטי, כל מי שיפתח "הצג מקור"
יכול לקחת אותו ולחייב את הכרטיס שלכם. לכן הקריאה ל-Claude עוברת דרך
`api/review-post.ts` — פונקציה קטנה שרצה בשרת, מחזיקה את המפתח אצלה, ומחזירה לדפדפן
רק את תוצאת הניתוח.

---

## שלב 1 — מפתח API

1. היכנסו ל-<https://console.anthropic.com> ← **API Keys** ← צרו מפתח חדש.
2. שמרו אותו במקום בטוח. הוא מוצג פעם אחת בלבד.

## שלב 2 — פריסה ב-Vercel

מהתיקייה הראשית של הפרויקט:

```bash
npm install -g vercel
vercel            # פריסת תצוגה מקדימה — עונים על השאלות עם ברירות המחדל
vercel --prod     # פריסה לייצור
```

Vercel מזהה את `api/review-post.ts` אוטומטית כפונקציה, ואת קובצי ה-HTML כאתר סטטי.
`vercel.json` כבר מגדיר לפונקציה חלון של 60 שניות.

## שלב 3 — משתני סביבה

בלוח הבקרה של Vercel: **Settings ← Environment Variables**. הוסיפו:

| משתנה | חובה? | ברירת מחדל | מה זה עושה |
|---|---|---|---|
| `ANTHROPIC_API_KEY` | ✅ חובה | — | המפתח משלב 1 |
| `ALLOWED_ORIGINS` | מומלץ | `https://shayvazana-oss.github.io` ועוד | רשימת דומיינים מורשים, מופרדים בפסיק |
| `RATE_LIMIT_PER_HOUR` | לא | `12` | מכסת ניתוחים לשעה לכל כתובת IP |
| `REVIEW_EFFORT` | לא | `high` | עומק החשיבה: `low` / `medium` / `high` |

אחרי שינוי משתנה יש להריץ `vercel --prod` שוב כדי שייכנס לתוקף.

> **חשוב:** אם האתר יישאר ב-GitHub Pages, ודאו ש-`ALLOWED_ORIGINS` כולל את
> `https://shayvazana-oss.github.io` — אחרת הדפדפן יחסום את הקריאה (CORS).

## שלב 4 — חיבור העמוד

בראש `linkedin-lab.html` יש שורה אחת לעריכה:

```html
<meta name="lab-api" content="">
```

הכניסו לתוכה את כתובת הפונקציה שקיבלתם מ-Vercel:

```html
<meta name="lab-api" content="https://bidul-ai-academy.vercel.app/api/review-post">
```

זהו. כפתור "נתחו את הטיוטה" בתחנה 4 מתחיל לעבוד.

> אם האתר עצמו נפרס ב-Vercel (ולא ב-GitHub Pages), אפשר להזין נתיב יחסי בלבד:
> `content="/api/review-post"`.

## הרצה מקומית

```bash
npm install
export ANTHROPIC_API_KEY=sk-ant-...
vercel dev            # מגיש את האתר ואת הפונקציה יחד על localhost:3000
```

בזמן פיתוח מקומי הגדירו `content="/api/review-post"` בתגית `lab-api`.

## בדיקות

```bash
npm run typecheck   # בדיקת טיפוסים לפונקציה
npm test            # 25 בדיקות לפונקציה מול Messages API מדומה
npx tsx tests/e2e-review.test.mts   # 20 בדיקות דפדפן מקצה לקצה
```

הבדיקות אינן צורכות מכסת API — הן עובדות מול שרת מדומה.

## מה הפונקציה עושה

* **מודל:** `claude-opus-5` עם חשיבה אדפטיבית (ברירת המחדל במודל הזה).
* **פלט מובנה:** הסכימה מוגדרת ב-Zod ונאכפת דרך `output_config.format`, כך
  שהתשובה תמיד חוזרת במבנה קבוע שהעמוד יודע לרנדר — בלי לנחש טקסט חופשי.
* **מה נשלח:** הטיוטה בלבד, ובנוסף חמשת שדות המיצוב מתחנה 2 אם מולאו.
* **מה לא נשמר:** הפונקציה חסרת מצב. הטיוטה אינה נכתבת לדיסק ואינה נשמרת בשום מסד נתונים.

### הגנות מובנות

| הגנה | פירוט |
|---|---|
| רשימת מקורות מורשים | בקשה מדומיין לא מוכר מקבלת 403 |
| מכסת קצב | 12 ניתוחים לשעה לכל IP (ניתן לשינוי) |
| תקרת קלט | מינימום 40 תווים, מקסימום 3,000 (המגבלה של לינקדאין) |
| תקרת שדות מיצוב | 200 תווים לשדה |
| טיפול בשגיאות | כל שגיאת API מתורגמת להודעה בעברית, בלי לחשוף פרטי שרת |

> **על מכסת הקצב:** היא נשמרת בזיכרון של מופע הפונקציה. זה עוצר שימוש
> מזדמן לרעה, אבל לא תוקף נחוש — מופעים מתחלפים והמונה מתאפס. אם העמוד
> ייחשף לקהל רחב, השלב הבא הוא מונה משותף (Vercel KV / Upstash).

## עלות

הניתוח שולח כ-1,000–1,500 טוקנים ומקבל כ-500–900 בחזרה. לפי תמחור Claude Opus 5
($5 למיליון קלט, $25 למיליון פלט), ניתוח בודד עולה בערך **2–3 סנט**.

מאה ניתוחים בחודש ≈ 2–3 דולר. `RATE_LIMIT_PER_HOUR` הוא הבלם שמונע הפתעות.
